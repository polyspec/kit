# Common standard checklist

## Kit

| ID | Task | Deliverables | Verification | State |
|---|---|---|---|---|
| K240 | The full suite runs only in CI. Cause: the full-run guard allows `make check` when no item is waiting or active, against PRINCIPLES.md, and no tool stops an agent from running a suite. Acceptance: no local command runs the full suite or a suite target, a suite target refuses outside a GitHub Actions run with the command that runs it in CI, and a vendored Claude Code PreToolUse hook refuses a Bash command that runs a suite target or a whole runtime without a selection, naming the command to use instead. | `scripts/kit/full-run.mts`, `scripts/kit/claude-hook.mts`, `.claude/settings.json` (vendored), `kit.mk` | `make kit-test` | [o] |
| K240-1 | The isolation test reads the imports of a module as Node.js reads them (follows K240). Cause: the test found imports with a regular expression over the text, so the option names `'--import'` and `'--require'` in a string of `scripts/kit/test-selection.mts` counted as imports of the specifiers `, ` and failed the rule. Acceptance: the test reads the imports through `parseModule` and `moduleImports` of `scripts/kit/module-imports.mts`, names a computed specifier as one that fails the rule, and passes. | `tests/kit/isolation.test.mts` | `node scripts/kit/run-tests.mts node -- tests/kit/isolation.test.mts` | [o] |
| K240-2 | The layout allows the folders of the Claude Code settings (follows K240). Cause: K240 added `.claude/` and the source `claude/` at the root, and layout-check refused both in the CI run of 7af0f5c; K240 had not run the owner check of the new paths. Acceptance: the common root folders of `config/layout.kit.yml` hold `.claude`, the place that Claude Code reads (S1), kit's `config/layout.yml` holds `claude` with its reason as it holds `workflows`, and layout-check passes. | `config/layout.kit.yml`, `config/layout.yml` | `make layout-check`, `node scripts/kit/run-tests.mts node -- tests/source/layout-real.test.mts` | [o] |
| K248 | Every rule is enforced where it cannot be skipped. Cause: most rules of PRINCIPLES.md and of each AGENTS.md hold only as text, and a check that nobody runs enforces nothing. Acceptance: every rule of PRINCIPLES.md and AGENTS.md carries an ID and `Enforced by:` with a check that the pre-commit, commit-msg or pre-push hook, the vendored Claude Code hook or the CI push-gate job runs, or `Enforced by: none` with the reason that no tool can enforce it; a kit check follows each named check from the hook and CI configuration and fails on a rule without the field, a check that no such point runs, and `none` without a reason; the Claude Code hook refuses `--no-verify`, a change of `core.hooksPath` and an edit of a vendored file; kit lists the rules that no tool enforces. | `scripts/kit/check-rules.mts`, `scripts/kit/claude-hook.mts`, `PRINCIPLES.md(.ko)`, `AGENTS.md(.ko)` | `make kit-test` | [ ] |
| K248-1 | Every repository runs the rebuild check and the rules check (follows K248). Cause: `make rebuild-check`, the check of S1, was a target of kit's own Makefile only, so no consumer ran it, and the rules check had no target. Acceptance: kit.mk defines `rebuild-check` and `rules-check`, kit's Makefile no longer defines `rebuild-check`, and a test of `tests/kit/gate-targets.test.mts` reads the command of each. | `scripts/kit/kit.mk`, `Makefile` | `node scripts/kit/run-tests.mts node -- tests/kit/gate-targets.test.mts` | [o] |
| K248-2 | The parity check decides whether a repository needs a parity declaration (follows K248). Cause: without `config/parity.json` the check failed in every repository, so a repository with one implementation, such as kit, could not run the check that enforces S6. Acceptance: without the declaration a checkout whose `packages/` holds at most one implementation folder (`packages/<runtime>` or `packages/<component>/<runtime>`) passes with a line that says so, and one that holds two or more fails and names them. | `scripts/kit/parity.mts`, `scripts/kit/parity-declaration.mts` | `node scripts/kit/run-tests.mts node -- tests/kit/parity.test.mts` | [o] |
| K249 | Plans, items and commits are written by utilities that share the checks of the hooks. Cause: a rule that a person or an agent applies by hand is broken by a slip, and a check that refuses after the fact makes the work again. Acceptance: `make plan-new NAME=<slug>` writes the four files of a plan with their doc-id and revision lines; `make item-new PLAN= ID= PARENT=` adds a row after checking that the ID is unique and the parent exists; `make item-state ID= STATE=` performs only an allowed transition, sets the done state only when the same commit holds the CHANGELOG entry of the item, and requires a cause and a retry condition for the bypassed state and a cause for the impossible state; `make commit ID=` writes the message in the commit format and refuses a commit that changes the state of more than one item; `make item-test ID=` runs the command of the Verification cell of the item, and a Verification cell whose command the Claude Code hook refuses (a suite or a run without a selection) fails the checklist check, so each item is tested by its own unit tests; each utility calls the same functions as the hooks, so its output passes them. | `scripts/kit/plan.mts`, `kit.mk` | `make kit-test` | [ ] |
| K241 | A plan is a folder with one plan and one checklist. Cause: every AGENTS.md allows one checklist per repository, which grows without bound, and kit checks item IDs within one checklist only. Acceptance: kit reads the checklists as `docs/plans/*/checklist.md`, each with `plan.md` and both Korean pairs beside it; a checklist without a plan, a plan without a checklist, another file in a plan folder, an item ID in two checklists and a sub-item whose parent is no item of its checklist fail with the file and line; `config/checklist.json` no longer lists paths. An existing checklist is split by its plans: each section or wave becomes the folder of its plan with its rows unchanged, an existing plan document becomes its `plan.md`, a section without one gets a `plan.md` written from its heading and background, and no catch-all plan holds rows that belong to no plan; the move is checked by the equal sets of rows before and after it. | `scripts/kit/checklist.mts`, `scripts/kit/schema/checklist.schema.json` | `make kit-test` | [ ] |
| K242 | A checklist is a table with five states. Cause: the repositories declare four or five states and the list or the table format. Acceptance: kit fixes the five states and the table format, and the schema refuses `states` and `format`, leaving the ID prefix as the only declaration of a checklist; a row whose number of cells differs from the header of its table fails with the file, the line and both counts. | `scripts/kit/checklist.mts`, `scripts/kit/schema/checklist.schema.json` | `make kit-test` | [ ] |
| K243 | The common rules of work are stated once. Cause: each AGENTS.md restates the commit, branch, checklist, test and idempotency rules in its own words. Acceptance: PRINCIPLES.md has a Workflow section that holds each rule that two or more AGENTS.md files state, kit's AGENTS.md keeps only kit's rules, and the commit types and limits are constants of the commit check. | `PRINCIPLES.md(.ko)`, `AGENTS.md(.ko)`, `scripts/kit/check-commits.mts` | `make kit-test` | [ ] |
| K244 | Tests are classified by location and selected by one command. Cause: each repository names and selects its tests differently. Acceptance: a test under `packages/<p>/tests/unit/` is a unit test, under `packages/<p>/tests/integration/` an integration test and under `tests/conformance/` a conformance test; `make test-<runtime> CASES=<pattern>` runs the selected unit tests through the filter of the runner; an integration or conformance target refuses outside CI; a selection that runs no test fails. | `scripts/kit/run-tests.mts`, `kit.mk`, `config/layout.kit.yml` | `make kit-test` | [ ] |
| K245 | The folder standard names one place for each concern. Cause: S5 allows `ts` and `js` for TypeScript sources, packages hold AGENTS, CHANGELOG and Makefile files, and the documents are laid out differently. Acceptance: the layout rules refuse a runtime folder that does not name its source language, a management file below the root, a test folder other than `tests/`, and a `docs/` layout other than `spec/`, `operations/`, `plans/` and `features.md`. | `config/layout.kit.yml`, `PRINCIPLES.md(.ko)` | `make kit-test` | [ ] |
| K246 | The make targets have fixed names. Cause: only `check` and `install` exist in most repositories, and one task has up to four names. Acceptance: kit.mk defines the names `install`, `build`, `test`, `lint`, `docs-check` and `build-<runtime>`, `test-<runtime>`, `lint-<runtime>` for each folder of `packages/`; a check fails for a package without its targets and for a target that repeats one of these tasks under another name. | `kit.mk`, `scripts/kit/kit-check.mts` | `make kit-test` | [ ] |
| K247 | A PHP extension follows one model and one build. Cause: the extensions follow five models, and repositories build the extensions of other repositories with scripts of their own. Acceptance: PRINCIPLES.md has S10: the extension registers the class names of the PHP library, lies in `packages/php-ext/src/` with one stub, is named `polyspec/<repository>-php-ext` and `polyspec_<repository>`, and is built by one kit tool with phpize, which generates its arginfo with gen_stub.php and fails when the stub hash in the header differs; the layout rules refuse another stub place or package name, and a kit declaration test fails when a class, method or signature that the extension registers differs from the PHP library. | `PRINCIPLES.md(.ko)`, `scripts/kit/php-extension.mts` | `make kit-test` | [ ] |
