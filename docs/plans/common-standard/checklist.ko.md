# 공통 표준 체크리스트

## Kit

| ID | Task | Deliverables | Verification | State |
|---|---|---|---|---|
| K240 | full suite는 CI에서만 돈다. 원인: full-run guard가 PRINCIPLES.md와 달리 waiting 또는 active 항목이 없을 때 `make check`를 허용하고, agent가 suite를 돌리는 것을 막는 tool이 없다. Acceptance: 어떤 local command도 full suite나 suite target을 돌리지 않고, suite target은 GitHub Actions run 밖에서 CI에서 그것을 돌리는 command를 알리며 거부하고, vendor된 Claude Code PreToolUse hook이 suite target이나 selection 없는 runtime 전체를 돌리는 Bash command를 대신 쓸 command를 알리며 거부한다. | `scripts/kit/full-run.mts`, `scripts/kit/claude-hook.mts`, `.claude/settings.json` (vendor), `kit.mk` | `make kit-test` | [ ] |
| K248 | 모든 규칙은 건너뛸 수 없는 지점에서 강제한다. 원인: PRINCIPLES.md와 각 AGENTS.md의 규칙 대부분이 text로만 존재하고, 아무도 돌리지 않는 check는 아무것도 강제하지 않는다. Acceptance: PRINCIPLES.md와 AGENTS.md의 모든 규칙은 ID와 `Enforced by:`를 가지고, pre-commit, commit-msg, pre-push hook, vendor된 Claude Code hook 또는 CI push-gate job이 돌리는 check를 명시하거나, `Enforced by: none`과 어떤 tool도 강제할 수 없는 이유를 명시한다. kit check는 명시된 check를 hook과 CI 설정에서 따라가며, field가 없는 규칙, 그런 지점이 돌리지 않는 check, 이유 없는 `none`에서 실패한다. Claude Code hook은 `--no-verify`, `core.hooksPath` 변경, vendor된 파일의 편집을 거부한다. kit은 tool이 강제하지 않는 규칙을 나열한다. | `scripts/kit/check-rules.mts`, `scripts/kit/claude-hook.mts`, `PRINCIPLES.md(.ko)`, `AGENTS.md(.ko)` | `make kit-test` | [ ] |
| K249 | plan, item, commit은 hook의 check를 공유하는 utility가 쓴다. 원인: 사람이나 agent가 손으로 적용하는 규칙은 실수로 깨지고, 사후에 거부하는 check는 작업을 다시 하게 만든다. Acceptance: `make plan-new NAME=<slug>`는 plan의 파일 4개를 doc-id와 revision 줄과 함께 쓴다. `make item-new PLAN= ID= PARENT=`는 ID가 유일하고 부모가 있는지 확인한 뒤 row를 추가한다. `make item-state ID= STATE=`는 허용된 전이만 수행하고, 같은 commit이 그 item의 CHANGELOG entry를 가질 때만 done state를 설정하며, bypassed state에 원인과 retry 조건을, impossible state에 원인을 요구한다. `make commit ID=`는 commit format으로 message를 쓰고 item 둘 이상의 state를 바꾸는 commit을 거부한다. 각 utility는 hook과 같은 함수를 호출하므로 그 출력은 hook을 통과한다. | `scripts/kit/plan.mts`, `kit.mk` | `make kit-test` | [ ] |
| K241 | plan은 plan 하나와 checklist 하나를 가진 folder다. 원인: 모든 AGENTS.md가 저장소당 checklist 하나를 허용하여 끝없이 커지고, kit은 item ID를 한 checklist 안에서만 검사한다. Acceptance: kit은 checklist를 `docs/plans/*/checklist.md`로 읽고 각각 옆에 `plan.md`와 두 한국어 짝이 있다. plan 없는 checklist, checklist 없는 plan, plan folder의 다른 파일, 두 checklist에 있는 item ID, 부모가 그 checklist의 item이 아닌 sub-item은 파일과 줄을 알리며 실패한다. `config/checklist.json`은 더 이상 경로를 나열하지 않는다. | `scripts/kit/checklist.mts`, `scripts/kit/schema/checklist.schema.json` | `make kit-test` | [ ] |
| K242 | checklist는 state 5개를 가진 table이다. 원인: 저장소가 state 4개 또는 5개와 list 또는 table format을 선언한다. Acceptance: kit이 state 5개와 table format을 고정하고, schema가 `states`와 `format`을 거부하여 ID prefix만 checklist의 유일한 선언으로 남는다. | `scripts/kit/checklist.mts`, `scripts/kit/schema/checklist.schema.json` | `make kit-test` | [ ] |
| K243 | 작업의 공통 규칙은 한 번 기술한다. 원인: 각 AGENTS.md가 commit, branch, checklist, test, idempotency 규칙을 각자의 문장으로 다시 기술한다. Acceptance: PRINCIPLES.md에 AGENTS.md 파일 둘 이상이 기술하는 규칙을 모두 가진 Workflow 절이 있고, kit의 AGENTS.md는 kit의 규칙만 가지며, commit type과 limit은 commit check의 상수다. | `PRINCIPLES.md(.ko)`, `AGENTS.md(.ko)`, `scripts/kit/check-commits.mts` | `make kit-test` | [ ] |
| K244 | test는 위치로 분류하고 command 하나로 선택한다. 원인: 저장소마다 test의 이름과 선택 방식이 다르다. Acceptance: `packages/<p>/tests/unit/` 아래 test는 unit test, `packages/<p>/tests/integration/` 아래는 integration test, `tests/conformance/` 아래는 conformance test다. `make test-<runtime> CASES=<pattern>`은 runner의 filter로 선택된 unit test를 돌린다. integration 또는 conformance target은 CI 밖에서 거부한다. test를 하나도 돌리지 않는 selection은 실패한다. | `scripts/kit/run-tests.mts`, `kit.mk`, `config/layout.kit.yml` | `make kit-test` | [ ] |
| K245 | folder 표준은 관심사마다 자리 하나를 정한다. 원인: S5가 TypeScript 소스에 `ts`와 `js`를 허용하고, package가 AGENTS, CHANGELOG, Makefile 파일을 가지며, 문서 배치가 서로 다르다. Acceptance: layout 규칙이 소스 언어를 이름으로 하지 않는 runtime folder, root 아래의 관리 파일, `tests/`가 아닌 test folder, `spec/`, `operations/`, `plans/`, `features.md`가 아닌 `docs/` 배치를 거부한다. | `config/layout.kit.yml`, `PRINCIPLES.md(.ko)` | `make kit-test` | [ ] |
| K246 | make target은 고정된 이름을 가진다. 원인: 대부분의 저장소에 `check`와 `install`만 있고, 한 작업이 이름을 최대 4개 가진다. Acceptance: kit.mk가 이름 `install`, `build`, `test`, `lint`, `docs-check`와 `packages/`의 folder마다 `build-<runtime>`, `test-<runtime>`, `lint-<runtime>`을 정한다. target이 없는 package와 이 작업 중 하나를 다른 이름으로 반복하는 target에서 check가 실패한다. | `kit.mk`, `scripts/kit/kit-check.mts` | `make kit-test` | [ ] |
| K247 | PHP extension은 model 하나와 build 하나를 따른다. 원인: extension이 model 5가지를 따르고, 저장소가 다른 저장소의 extension을 각자의 script로 build한다. Acceptance: PRINCIPLES.md에 S10이 있다. extension은 PHP library의 class 이름을 등록하고, stub 하나와 함께 `packages/php-ext/src/`에 있으며, 이름은 `polyspec/<repository>-php-ext`와 `polyspec_<repository>`이고, kit tool 하나가 phpize로 build한다. 그 tool은 gen_stub.php로 arginfo를 생성하고 header의 stub hash가 다르면 실패한다. layout 규칙은 다른 stub 위치나 package 이름을 거부하고, kit declaration test는 extension이 등록한 class, method, signature가 PHP library와 다르면 실패한다. | `PRINCIPLES.md(.ko)`, `scripts/kit/php-extension.mts` | `make kit-test` | [ ] |
